# Adding a new tool

Checklist for adding a new tool module (example: `jbase64`). Overall structure and
conventions are described in [development.md](development.md).

## 1. Module

```shell
mkdir -p jbase64/src/main/java/de/mhus/jknife/jbase64 jbase64/src/test/java/de/mhus/jknife/jbase64
```

- `jbase64/pom.xml`: copy from `jregex/pom.xml`, adjust `<artifactId>`, `<name>`,
  `<description>`.
- Main class `JBase64Cmd` in package `de.mhus.jknife.jbase64`, with:

  ```java
  public static final String VERSION = "0.0.1-SNAPSHOT"; // kept in sync by scripts/set-version.sh
  ```

  Subcommands as separate classes (like `MatchCmd`, `FindCmd`), shared input handling in
  a mixin (like `RegexInput`).

## 2. Register the module

- parent `pom.xml`: add `<module>jbase64</module>`
- if new shared helpers are needed: put them in `jknife-shared`, not in the tool

## 3. Release integration

- `.github/workflows/release.yml`: add the tool to the artifact loop
  (`for TOOL in jregex jbase64; do ...`)
- `scripts/gen-formula.sh`: add the tool to the `TOOLS` array and its description to
  `desc_of()`

## 4. Tests & docs

- unit tests + CLI tests like `JRegexCliTest` (exit codes are part of the contract)
- `README.md`: add a row to the tools table
- `docs/`: user doc `docs/<tool>.md` + entry in `docs/index.md` (GitHub Pages)
- tap repo: the formula is generated by `scripts/gen-formula.sh`, nothing to do here

## Checklist

```
[ ] module created (pom copied & adjusted)
[ ] main class <Tool>Cmd with VERSION constant
[ ] registered in parent pom <modules>
[ ] added to release.yml artifact loop
[ ] added to gen-formula.sh TOOLS + desc_of
[ ] tests (unit + CLI incl. exit codes)
[ ] README tools table updated
[ ] user doc: docs/<tool>.md + entry in docs/index.md
[ ] mvn verify is green
[ ] native build works: mvn -Pnative package
```
